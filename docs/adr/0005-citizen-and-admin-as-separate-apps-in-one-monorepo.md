# Citizen and Admin ship as separate apps from one monorepo

The Citizen PWA and the Admin panel become two Next.js apps in a pnpm monorepo — `apps/citizen`, `apps/admin`, with shared domain code in `packages/core` (`settimana-tipo`, `waste-style`, `group-collections`, types, i18n, Supabase client factories) and `supabase/` at the root. They deploy as two Vercel projects: the Citizen app on the public domain, Admin on `admin.differenziacomiso.it`. The `/admin/*` routes are deleted from the Citizen app and 404 — no redirect, because a redirect re-publishes the address we moved to hide.

We do this for two reasons only: the Admin panel is not discoverable from the citizen domain, and Admin's JavaScript never ships to a citizen's phone. Both apps are also drifting toward opposite layouts — Admin is desktop-first and operator-facing, the Citizen app is a 480px offline-capable PWA — so a shared root layout was becoming a tax.

**It buys no security isolation, and must not be described as if it did.** Both apps talk to the same Supabase project with the same anon key, and both deploys carry `SUPABASE_SERVICE_ROLE_KEY`: the Citizen app keeps `/api/push/subscribe`, `/api/push/unsubscribe` and the daily cron (its origin calls them, its `vercel.json` schedules them), while `/api/push/send` and `/api/push/subscribers` move to Admin. The real authorization boundary remains where [ADR 0003](./0003-db-layer-admin-authorization.md) put it: `admins`-table membership enforced in Postgres RLS.

**Considered and rejected: two separate repositories.** It was the starting proposal, on the theory that a compromise of one app would not reach the other — which the paragraph above disproves. Its actual cost is permanent: `supabase/migrations/` can only live in one repo while both depend on the schema, `settimana-tipo` is needed by both the Admin import tool and the seed script, and `CONTEXT.md` and `docs/adr/` would fork. A monorepo delivers both real benefits with one CI, one glossary, and one migration history. If Admin is ever handed to a separate operator, extracting a package into its own repo is a day's work — do it then, with a reason.

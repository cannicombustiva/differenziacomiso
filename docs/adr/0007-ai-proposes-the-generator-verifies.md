# The AI Import proposes; the Settimana Tipo generator verifies

The Admin calendar gains an Import tool: an Admin attaches the Busso PDF for a date range (whole year by default), a Claude model reads it and returns the full set of Pickups for that range **plus** its own inferred weekly pattern and its own list of Exceptions, and none of it is written until the Admin approves. `settimana-tipo` generates the same range deterministically alongside it, and the review screen shows only the **Divergences** — the dates where the two disagree. In a normal year that collapses ~365 rows to the ~15 real Exceptions.

The review is the point. Asking an Admin to approve 365 model-generated rows is approval theatre: nobody reads them, everybody clicks Approve, and one hallucinated Thursday in August sends a whole town the wrong instruction at 20:00 — a Notification that cannot be recalled. Diffing against tested code is what makes the approval real, and it reuses the discipline already in `scripts/generate-seed.ts`, which prints a semantic old→new diff for human review rather than writing silently.

Three rules follow from that:

- **A pattern change blocks the Import.** If more than four Divergences share the same weekday and shape, the Settimana Tipo itself has changed. The tool refuses and directs the Admin to update `packages/core/settimana-tipo.ts` and its tests, then re-import. Absorbing a pattern change as 52 individual one-off rows would leave the generator quietly describing a schedule that no longer exists.
- **Approval is a transactional range replace** — delete the range, insert the approved rows — per [ADR 0001](./0001-schedule-stores-final-state.md), preceded by a warning listing any hand-entered Exceptions inside the range that the replace would destroy. Merging row-by-row would mean the stored Schedule is not what the Admin approved.
- **Everything is retained.** `schedule_imports` keeps the source PDF (private Storage bucket — a public municipal document is still a URL that cannot be un-published), the raw model output, the approved diff, the approving Admin, and a status of `draft | approved | discarded`, so an abandoned Import is evidence too. Approving an Import writes the matching Coverage row ([ADR 0006](./0006-coverage-is-explicit-absence-is-not-evidence.md)).

**The model is deliberately left open.** The call goes through the Vercel AI Gateway with the AI SDK, so the model is a string and a thinking-config option; the schema, the diff, the block rule and the apply path do not change with it. `seed.sql` is ground truth for 2026, which makes model selection an experiment rather than an argument: run the 2026 PDF through a candidate and count its Divergences against the known Exception list. `scripts/generate-seed.ts` is kept for exactly that reason — it is the executable proof that `settimana-tipo` reproduces the published year — and is **not** a second path for loading new years. New years come through Import only.
